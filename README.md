# Fujiwara Tofu Shop — Final Project

Новая версия проекта с нуля на **React 19 + Vite**, без Bootstrap и jQuery.

**Команда letsgo:** Dastan и Beibarys · **SE-2516** · Astana IT University.
Прошлые задания в соседних папках не изменены. Язык интерфейса — английский, как в предыдущих версиях.

## Запуск

Нужен Node.js 22 или новее.

```bash
cd final-project
npm ci
npm run dev
```

Открой адрес, который выведет Vite: обычно **http://127.0.0.1:5173**. В подготовленной рабочей папке зависимости уже есть, поэтому можно сразу выполнить `npm run dev`.

```bash
npm test
npm run build
npm run preview
```

Готовый сайт находится в `dist/`. Его нужно отдавать через HTTP/HTTPS. Открытие `index.html` двойным щелчком не запускает React-приложение.

## Данные и формы

Главный ролик взят из предоставленного GIF Initial D. Для сайта он перекодирован в H.264 MP4: **8 055 105 → 633 277 байт**, почти в 13 раз меньше при сохранении 109 кадров, 20 fps и длительности 5,45 секунды. `HeroMedia` показывает предварительно загруженный WebP, проигрывает видео без звука один раз, затем оставляет точный исходный последний кадр. При reduced motion, ошибке видео или запрете autoplay используется статичное изображение. Исходный GIF находится в `assets/source/`, а не в публичной сборке. Версии MP4/WebP в `public/media/` имеют хеши в именах и годовой immutable-cache из `vercel.json`. Повторная генерация: `python tools/optimize_hero.py` (нужен FFmpeg).

При первом открытии включена чёрная тема. Переключатель меняет фон всей страницы, текст, поля и карточки; выбранная тема сохраняется после переходов и перезагрузки и синхронизируется между вкладками. До запуска React применяется тот же сохранённый выбор, чтобы избежать вспышки светлого фона.

Регистрация — учебная симуляция, а не настоящий сервис авторизации. В localStorage сохраняются профиль и SHA-256 хеш пароля с индивидуальной солью; читаемый пароль не сохраняется. Для демонстрации используй вымышленные данные и отдельный пароль, например `Skyline#34`. Требования: минимум 8 символов, заглавная и строчная буква, цифра, специальный символ. Работает на localhost или HTTPS.

Контактная форма отправляет сообщение владельцу проекта через Telegram: браузер вызывает `/api/contact`, сервер повторно проверяет поля и вызывает Bot API. Только подтверждённая доставка показывает успех; после неё в браузере сохраняется копия для истории профиля. Старые локальные черновики помечены отдельно. Токен и chat ID находятся только в серверных переменных окружения. Гостевые избранные машины не переносятся в аккаунт автоматически; интерфейс объясняет разделение.

localStorage: `jdm:theme`, `jdm:accounts`, `jdm:session`, `jdm:garages`, `jdm:filters`, `jdm:messages`. Очистка данных сайта удаляет локальные аккаунты и коллекции. Для работы API нужен интернет; ключ не требуется. При недоступной сети отображается сообщение и кнопка повтора, а не вымышленные данные.

## Подключение Telegram

1. В `final-project/.env.local` задать `TELEGRAM_BOT_TOKEN` (без префикса `VITE_`). Файл исключён из Git; шаблон — `.env.example`.
2. Владелец открывает бота в Telegram и отправляет `/start`.
3. Выполнить `npm run telegram:setup`, выбрать свой приватный чат из списка. Скрипт проверяет чат и сохраняет `TELEGRAM_CHAT_ID` в `.env.local`. Если команда запущена до `/start`, отправить команду боту и повторить настройку. У бота с существующим webhook нужно получить chat ID через его обработчик и передать `--chat-id ID`; настройка не удаляет чужой webhook.
4. Проверка настоящим уведомлением: `npm run telegram:setup -- --test`. Эта команда действительно отправляет тестовое сообщение выбранному владельцу.
5. В Vercel → Project Settings → Environment Variables добавить **обе** переменные для Production (при необходимости также Preview), затем сделать новый deploy. Локальный `.env.local` на Vercel не загружается.

`npm run dev` обслуживает `/api/contact` локально через Vite middleware с тем же серверным обработчиком. После изменения `.env.local` перезапустить dev-сервер. Production использует Vercel Function `api/contact.js`; простой `vite preview` и GitHub Pages серверную функцию не запускают. Токен никогда не помещается в React, `public/` или `VITE_*`.

Поля проверяются и на клиенте, и на сервере. Сообщение — до 3000 символов, JSON — до 16 КБ; отправка идёт plain text без HTML-разметки. Получатель задаётся сервером, входящий `chat_id` игнорируется. Есть timeout, обработка Telegram 429 и ошибок доставки. Кнопка блокируется на время запроса; при неопределённом результате показано предупреждение о возможном дубликате. Публичная форма не имеет CAPTCHA или распределённого ограничения частоты: при необходимости его можно задать в Vercel Firewall.

API-тесты используют подставной Bot API, браузерные тесты и сборщик снимков — контролируемый ответ `/api/contact`. Они не отправляют уведомления и не доказывают работу настоящего бота.

Официальные источники: [Telegram Bot API](https://core.telegram.org/bots/api#sendmessage), [получение обновлений](https://core.telegram.org/bots/api#getupdates), [Vercel Functions](https://vercel.com/docs/functions/runtimes/node-js), [переменные окружения](https://vercel.com/docs/environment-variables).

## Проверки

`npm test` проверяет валидацию, хеширование/хранилище, рендеринг всех 16 маршрутов, внутренние ссылки, наличие заголовков, форм и подписей, а также профиль с сохранёнными данными. `npm run build` создаёт production-сборку.

Для настоящей проверки интерфейса и скриншотов:

```bash
npx playwright install chromium
npm run build
npm run test:browser
```

Тест запускает preview-сервер, проверяет пользовательские сценарии, обе темы, 320/390/768/1440 px, навигацию, вход/выход, поиск, избранное, формы и контролируемые ответы API. Скриншоты сохраняются в `docs/screenshots/`, результат — в `docs/browser-results.json`. Проверки API используют фиксированные ответы и ошибки: отдельно открой `#/drive` с интернетом для проверки живого сервиса. Если браузер уже установлен, можно передать `CHROMIUM_PATH`; `BASE_URL` позволяет проверять уже работающий preview.

**Фактический статус проверки:** 16 тестов логики/рендеринга, production-сборка и 110 браузерных проверок проходят. Сделаны 26 реальных снимков страниц, включая desktop/mobile, обе темы, формы, профиль и состояния API; живой запрос Open-Meteo прошёл отдельно. Ранее запуск браузера блокировался окружением, после включения полного доступа проверки выполнены. Live-сайт: https://final-web1-g3gm.vercel.app/ (HTTP 200 проверен). Оптимизированный MP4 уже работает на production; подтверждены один проход, последний кадр, reduced motion и кеширование.

## Публикация

Рабочий сайт: **https://final-web1-g3gm.vercel.app/**. Исходники: **https://github.com/lackoftalentt/final-web1**.

Проект опубликован на Vercel. Для обновления используй содержимое этой папки: Framework — Vite, Build Command — `npm run build`, Output Directory — `dist`. Vercel подключён к GitHub: push в `main` автоматически запускает production-деплой. Это проверено коммитом `8a4ecab`; вручную нажимать Redeploy не потребовалось.

`vercel.json` задаёт сборку и долгий кеш только для хешированных `/media/` и `/assets/`. У новых медиа другие имена, поэтому браузер получает новую версию после обновления. HTML не получает годовой immutable-cache.

**Production проверен:** загружается MP4 633 277 байт, запросов GIF нет. Ролик играет один раз и остаётся на последнем кадре; reduced motion не загружает видео. Для хешированного медиа подтверждён `Cache-Control: public, max-age=31536000, immutable`. Результат записан в `docs/production-check.json`.

Workflow `Check JDM Legends` запускает тесты и сборку при push и pull request. Альтернативная публикация GitHub Pages сохранена в `.github/workflows/pages.yml`, но запускается только вручную с `deploy_pages: true`; production-хостинг использует Vercel.

## Подготовка сдачи

```bash
python -m pip install reportlab Pillow
npm run report
```

`npm run report` запускает тесты, production-сборку и настоящий Chromium, снимает 26 состояний страниц, затем собирает PDF, ZIP и TXT. Для снимков используется отдельный профиль с вымышленными данными; личные аккаунты в браузере пользователя не затрагиваются. Нужен обычный терминал, где разрешены запуск браузера и локальный сервер. Скрипт использует установленный Chrome/Chromium; путь можно задать через `CHROMIUM_PATH`. Если браузер не установлен: `npx playwright install chromium`.

Сведения о команде и ссылках сохранены в `docs/report-details.json`: Dastan — About Us, Culture и Profile; Beibarys — остальные страницы и функции. Репозиторий: https://github.com/lackoftalentt/final-web1. В `live_url` указан текущий адрес Vercel. Оптимизированная сборка опубликована на этом же проекте; дальнейшие push в main обновляются через Vercel CD.

Скрипт создаёт соседнюю папку `final-project-submission` с тремя файлами по правилам PDF:

- `JDM_Legends_SE2516_FinalProject.zip` — исходники и готовая сборка, без node_modules.
- `JDM_Legends_SE2516_Report.pdf` — все пять обязательных разделов, подробное описание текущего сайта, реальные снимки с подписями, проверка по рубрике и план защиты.
- `JDM_Legends_SE2516_Links.txt` — подтверждённый репозиторий и фактический live-адрес после публикации.

PDF честно отмечает недостающие скриншоты и публикацию. Изображения добавляются только при совпадении контрольных сумм снимков и fingerprint текущей сборки. Для обновления текста PDF из уже снятых изображений, без нового браузера:

```bash
python tools/prepare_submission.py
```

Манифест реальных снимков: `docs/report-captures.json`; PNG: `docs/screenshots/report/`. Успех API с контролируемым тестовым ответом всегда подписан отдельно от живых данных. При ошибке скрипт сохраняет результат и завершает команду с ненулевым кодом, сохраняя честный статус отчёта.

Сценарий выступления на 4:30–5:00 — в [DEFENSE.md](docs/DEFENSE.md). Каждый участник загружает все три файла в Moodle до **18.11.2026 23:59**. ZIP/PDF/TXT должны соответствовать окончательной опубликованной версии.
